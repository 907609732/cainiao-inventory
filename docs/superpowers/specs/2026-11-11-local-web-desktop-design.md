# 菜鸟云仓：本机网页、应用与 AI 共用后台

状态：用户已于 2026-11-11 确认，实施中。基线提交：65e4608，版本 0.9.7。

## 目的与范围

用户希望同一款菜鸟云仓既能从 Windows 应用启动，也能通过网页使用，方便 AI 调用。用户已同意先做本机网页服务、应用与网页共用后台的方向。

第一阶段提供 Windows 安装包中的两个启动入口：菜鸟云仓、菜鸟云仓（网页版）。浏览器界面与应用共用库存、销量、设置、通知与任务状态。API 和 MCP 直接调用同一业务服务。这里的网页端是本机服务，仍需本机安装并运行后台；不是上传网站或纯静态离线页面。

本次实现以临时配置、虚构数据验收。正式数据、已安装程序、相邻电商工作台及其安装身份不在开发阶段改动。发布安装、正式升级另按用户后续指令执行。

## 当前代码约束

- `desktop/main.mjs` 集中持有 Windows safeStorage、设置、任务进程、自动任务、更新器与 Electron IPC。
- `desktop/preload.cjs` 向四个页面注入 `window.inventoryApp`，页面通过该对象访问业务。浏览器没有这个对象；现有 CSP 也禁止网络连接。
- 桌面启动使用 Electron 单实例锁，但 CLI/MCP 分支跳过该锁。MCP 当前会调用独立 CLI 子进程，因此不能简单再启一个定时器或绕过现有任务锁。
- 已有基于文件独占创建的任务锁、库存校验、日期异常确认服务及多渠道发送，可继续复用。
- 历史 `desktop/workbench/server.mjs` 是电商工作台测试网关，有其专属路径和隔离要求，且独立安装包排除了它。不能将其直接作为独立云仓网页后台。

## 方案比较

1. **保留 Electron 单一后台，增加本机 HTTP 接口（推荐）。** 继续复用 safeStorage、采集子进程、现有更新器及独立数据目录；桌面窗口和浏览器连接同一服务。无需用户额外安装 Node，接入成本集中在业务适配与启动生命周期。
2. **拆成纯 Node 服务与 Electron 客户端。** 适合将来跨系统服务器部署，但当前需重做 Windows 密钥解密、登录环境、调度与更新分工，改动显著更大。
3. **直接复用旧工作台网关。** 依赖工作台测试环境与身份，违背独立软件目标，不采用。

第一项是对已确认方向的具体技术提案，并非用户已确认全部细节。

## 开源复用与环境

- 现有 Fastify 5.12.5，MIT；[仓库](https://github.com/fastify/fastify)，[对应版本文档](https://github.com/fastify/fastify/tree/v5.12.5/docs)。Node 24.18.0/npm 11.16.0 已可用，无需系统环境安装。调研时官方仓库仍在维护。
- 静态资源采用官方 [@fastify/static](https://github.com/fastify/fastify-static)，MIT，8.x 支持 Fastify 5。实施时锁定通过最小验证的兼容版本，保留许可证。
- AI 复用已安装 `@modelcontextprotocol/server` 2.4.0，Apache-2.0，[官方 SDK](https://github.com/modelcontextprotocol/typescript-sdk)，继续提供 stdio 接入；首期不另加第二套 HTTP MCP 框架。已有 REST API 可供 HTTP 型调用端使用。
- 状态更新先采用经过鉴权的定时查询与增量日志游标，避免首期增加 SSE 框架、重连与敏感事件广播的复杂度。无需 React/Next.js 重写现有页面。
- GitHub 搜索与 Context7 已核对项目和兼容文档。Grep MCP 检索返回 504，使用 GitHub 代码搜索核对官方 MCP 本机服务示例作为替代。find-skills 已读取本地方法及技能目录，当前已有规划、浏览器验收技能足够，不引入未经审核的新 Skill。

## 唯一后台与启动方式

- 新增 `--web`：启动后台，打开本机默认浏览器，不创建业务窗口；重复启动只打开已有服务。
- 普通双击：启动或找到同一用户配置目录下的后台，打开应用窗口。
- 使用同一独立 profile 和 Electron 单实例协调。第二次启动携带的模式参数由已有实例处理；禁止另外启动调度器或数据库写入服务。
- 后台只绑定 `127.0.0.1`，默认固定端口由实施时检查避开已知工作台端口后确定；端口占用时验证本产品实例身份，若非本产品则明确报错，不盲目连接或静默换成未知地址。
- 浏览器和应用窗口关闭后，后台继续运行；托盘提供“打开应用”“打开网页版”“退出菜鸟云仓”。退出时统一停止服务及调度，有进行中的任务需明确提示；不会以关闭网页代表停止任务。
- 启动入口需要本机用户登录，不提供 Windows 系统服务或注销后继续任务。现有开机启动开关保留，已关闭的配置不自动开启。
- CLI/MCP 优先连接当前后台；需要时通过同一协调机制启动无窗口后台。查询不启动同步；退出 MCP 客户端不退出共享后台。保留旧 CLI 参数兼容和托管模式边界。
- 为避免旧已安装版本与开发版抢占 profile，开发与验收使用独立临时 profile；正式升级需走安装测试及备份流程。

## 业务与界面适配

- 抽出显式的业务操作表，供 Electron IPC、HTTP 与 CLI/MCP 适配器调用。不能将任意 IPC 名称、文件路径或 JS 方法透传为 HTTP。
- 复用四个页面、现有图表与表格；浏览器增加 `window.inventoryApp` 的 HTTP 适配器。桌面保留 IPC 适配器，二者共享 DTO 与错误码。
- 只暴露页面、样式、品牌图片、loading 组件及指定 ECharts/Grid.js 发布文件。不能以项目根目录或整个 node_modules 作为静态目录；数据、设置、密钥、日志原文件、源码及目录列表都不可被静态读取。
- 浏览器 CSP 允许同源请求，禁止任意跨域和内联代码。已有相对依赖路径需要映射成明确的前端资源地址，不能放开整个文件系统。
- 网页支持查询、筛选、配置保存、同步、月销量采集、多渠道通知及现有日期异常弹窗。
- 密钥字段在浏览器仅显示“已配置”，用户可替换，不提供现有明文回读；空白保留原值，清除采用显式操作。AI API 不提供密钥读取接口。
- “打开数据/日志目录”仅允许打开预先指定的本机目录；外部站点保持现有官网/GitHub 白名单。
- 软件更新由桌面后台持有。网页可检查更新，但安装重启必须由桌面窗口明确确认，不提供 AI 直接安装更新或任意程序执行接口。

## API 与 AI 权限

- `/api/v1/health` 仅返回服务品牌、版本及协议版本，不含数据与凭据。
- 查询接口覆盖库存、月销量筛选、任务状态、脱敏日志与 capabilities；API 文档采用明确的请求/响应格式。
- 任务接口返回 taskId，并提供状态查询；同步、发送和月报等继续使用同一任务锁。请求超时不等于任务失败，客户端不得因断线自动重复发送。
- AI 接入说明同时提供 stdio MCP 配置和 REST 示例；新增库存/销量查询工具，不仅提供原有诊断工具。
- 同步/发送接口保留明确的副作用确认字段及请求幂等键；AI 不因获得查询凭据而自动获得写入权限。默认 AI 凭据只读，写入权限由本机设置显式开启。
- 日期异常发送沿用两分钟、单次确认凭据及所有证据复核，凭据绑定会话/身份；预览不能触发发送。其他校验错误仍拒绝。

## 本机访问验证

- 本机不代表任意网页都有权限。校验 Host 与 Origin，不开启通配 CORS，拒绝跨站表单和非法内容类型。
- 浏览器入口使用每次启动生成的短期一次性交换凭据（URL fragment），交换后立即清除 fragment，建立 HttpOnly、SameSite=Strict 会话；修改操作附带 CSRF 校验。凭据不写访问日志，不用 query 参数传递长期密钥。
- AI 使用独立的可撤销本机 Bearer 凭据，与浏览器会话隔离。凭据由本机设置生成并显式显示供配置，不自动注入其他应用；磁盘存储继续加密，日志脱敏。
- HTTP 路由进行严格字段、范围、大小校验。不得将请求中的数据目录、可执行文件、Shell 参数用于任意本机操作。

## 验收条件

1. 桌面先启动/网页先启动，重复点击启动入口，始终只有一个后台和一组调度；两端看到同一任务状态。
2. 使用虚构库存、销量、设置和本地模拟通知端验证两端展示与配置同步，正式数据不参与测试。
3. 多端同时请求同步/发送时仅有一个任务；模拟超时重试不会重复投递。日期异常预览、取消、确认、过期与并发规则保持有效。
4. 未授权、跨站、错误 Host、过期会话、路径穿越、静态读取密钥/数据库及只读 AI 写入均被拒绝。
5. 网页关闭后后台存活，重新打开恢复状态；托盘退出可干净关闭。后台不存在、端口冲突及服务退出时页面给出明确状态。
6. 源码浏览器与 Electron 测试、现有回归及打包后测试通过。安装包在隔离 Windows 验证两个入口、升级保留测试数据及电商工作台共存。
7. 交付说明列出源码、打包与真实平台投递各自的验收范围；模拟投递不宣称真实平台送达。
