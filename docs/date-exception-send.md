# 库存日期异常时的特殊发送

0.9.7 增加“特殊发送日期异常库存”按钮。仅当最新库存校验失败的唯一原因是来源日期偏旧、文件仍与原校验摘要一致时，独立版运行概览才显示该按钮。未来日期、混合日期、数量或格式问题、库存不平、重复 SKU、跨日不连续等均不能通过该入口发送。

点击按钮后会显示确认弹窗，列出期望来源日期、文件实际日期、行数、库存合计及已启用的接收渠道。取消或关闭弹窗不会发送；只有再次点击“我已了解风险，确认发送”才会调用通知渠道。

例如期望 2026-11-01、实际 2026-10-31 时，可人工确认发送这份 10-31 的文件。报告标题与正文明确写出“日期异常”和两种日期，不会把文件日期改成 11-01，也不会悄悄换用其他账本快照。

此操作只发送本次文件的报告，不导入正常库存，不把失败校验改成通过，也不标记正常同步成功。发送记录单独写入独立版 workspace/state/date-exception-sends.jsonl。

确认凭据两分钟有效、只能用一次。发送前重新检查文件、基线、最新校验记录、接收配置和时限；任何改变都必须重新确认。已受理、部分受理或结果不明时不允许直接重复发送，避免重复消息。托管模式仍走其中央复核流程，不提供此独立版按钮。

测试使用临时 SQLite、虚构 XLSX 和本地 HTTP 模拟服务，覆盖显示、取消、确认、文件替换、配置变化、异步读取期间变化、并发确认、过期、其他校验失败和重启后的审计去重；未读取正式业务数据或发送真实渠道消息。本功能尚未替换电脑上的 0.9.6。
